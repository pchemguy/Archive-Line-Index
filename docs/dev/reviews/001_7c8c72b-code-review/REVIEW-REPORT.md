### U-001 — Public surface, source detection, offset model and scanner

- **C-001 (Public API, validation, source types and error categories):** Satisfied across `src/archive_line_index/__init__.py:L1-L40`, `src/archive_line_index/errors.py:L4-L33`, `src/archive_line_index/sources.py:L7-L22`, `src/archive_line_index/scanner.py:L22-L30`, and `src/archive_line_index/api.py:L14-L69`. `__all__` exports the exact 19 public symbols required by `docs/dev/decomposition/public-api.md:L120-L135` without leaking internal readers, format enums, worker controls, or `cli.main`. `normalize_source` rejects `bytes`, `PathLike[bytes]`, and non-path objects with `TypeError` before any filesystem open. Both `open_content_stream` (`api.py:L33-L34`) and `build_line_index` (`api.py:L61-L63`) validate all non-I/O options (`skip_utf8_bom`, `buffer_size`, `max_uncompressed_size`, and `source` type) before calling `detect_format` or `open_backend`.
- **C-002 (Byte fidelity, LF/BOM rules, canonical Q/eight-byte offsets and EOF sentinel):** Satisfied across `src/archive_line_index/offsets.py:L9-L62` and `src/archive_line_index/scanner.py:L32-L102`. `_validate_representation` and `validate_offsets` enforce concrete `array("Q")` instances with `itemsize == 8`, initial offset `0` or `3`, strict monotonicity, singletons restricted to `[0]` and `[3]`, and values within `0..2^63 - 1` (`MAX_OFFSET`). `scan_line_offsets` validates `callable(getattr(stream, "read", None))` and `offsets.itemsize == 8` before reading (`scanner.py:L77-L81`), probes the first 3 bytes using `min(buffer_size, 3 - len(prefix))` so read requests never exceed `buffer_size` even for `buffer_size < 3` (`scanner.py:L84-L89`), checks `check_position(end)` before appending block offsets (`scanner.py:L40-L41`), searches blocks via `block.find(b"\n", start)` without retaining lines (`scanner.py:L43-L45`), and leaves the borrowed stream open on all success and failure paths.
- **Source detection (`formats.py`):** Signature precedence over suffix claims, case-insensitive compound suffix matching (`.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz`, `.tbz2`, `.tar.xz`, `.txz`, `.zip`, `.7z`), and TAR 512-byte header checksum / non-zero prefix discrimination match `docs/dev/spec/archive-handling.md:L10-L15`, except that `detect_format` opens the inspection handle with default `io.BufferedReader` buffering (`R-001`).

### U-002 — Common stream, backend protocol and ownership

- **C-001 (Public stream surface, validation and state precedence):** Satisfied across `src/archive_line_index/stream.py:L12-L204` and `src/archive_line_index/backends/base.py:L6-L33`. `ContentStream.__init__` raises `TypeError` (`stream.py:L29-L30`). `_check_open` raises `ValueError` on a closed stream before argument validation or retained failure checks across `read`, `readinto`, capability queries (`readable`, `writable`, `seekable`), rejection methods (`seek`, `tell`, `write`), and `__enter__`. On a nonclosed stream, `read` and `readinto` validate arguments (`TypeError`) before raising any retained `_failure`, and check `_failure` before zero-length early returns (`read(0)`, `readinto(bytearray())`). `readinto` casts writable C-contiguous buffers to `"B"`, releases the intermediate `memoryview` in `finally` (`stream.py:L117-L126`), measures capacity in bytes for nonbyte element arrays, preserves unused buffer tails, and leaves the destination untouched when `_read_block` fails.
- **C-003 (Owned resource transfer, cleanup notes and retry):** Satisfied across `src/archive_line_index/stream.py:L45-L56, L168-L234` and `src/archive_line_index/backends/plain.py:L23-L37`. `make_content_stream` consumes `reader` ownership on entry (`stream.py:L206-L234`) and closes `reader` (attaching a `Payload cleanup failed` note on secondary cleanup error) if limit validation or declared-size checks fail. `_release` clears `self._reader = None` only after `self._reader.close()` returns normally (`stream.py:L45-L48`), and `close()` sets `self._closed = True` only after `_release()` succeeds (`stream.py:L168-L173`), allowing `close()` to be retried after a transient cleanup failure without falsely claiming `closed=True`. `__exit__` and `_fail` preserve the primary exception and attach cleanup notes (`stream.py:L50-L55, L186-L191`). However, `open_plain_backend` opens plain files with default `BufferedReader` buffering (`R-002`).
- **C-004 (Terminal validation, inclusive limits and error categories):** Satisfied in `src/archive_line_index/stream.py:L57-L105` and `src/archive_line_index/backends/registry.py:L11-L32`, with one recommendation on the internal `open_backend` seam (`R-003`). `_read_block` bounds backend requests to `min(size, self._limit - self._accepted + 1)` (`stream.py:L61-L62`), raising `SizeLimitExceededError` when `_accepted > _limit` and requiring `self._reader.completed` when `data == b""` (`stream.py:L69-L74`), including when a payload is exactly at `max_uncompressed_size`. Unbounded `read(-1)` discards accumulated blocks if a late error occurs (`stream.py:L97-L105`).

### U-003 — ZIP and plain/gzip/bzip2/xz TAR adapters

- **C-003 (Owned resource lifecycle, bounded reads and no payload extraction):** Satisfied across `src/archive_line_index/backends/zip.py:L27-L41, L121-L152` and `src/archive_line_index/backends/tar.py:L89-L103, L106-L109, L153-L168, L170-L204`. Both adapters register acquired handles in LIFO order (`[member, archive, source]` for ZIP; `[member, archive, decoded, source]` for compressed TAR) and release them through `_close_resources`, removing only resources whose `close()` succeeded and chaining secondary cleanup exceptions as notes (`ZIP cleanup failed` / `TAR cleanup failed`). Opening failures release any already-acquired handles and attach `ZIP opening cleanup failed` / `TAR opening cleanup failed` notes on cleanup errors. Member names (including unsafe traversal names such as `../folder/data` and `/abs/path`) are never used as filesystem paths (`archive.open(info)` in ZIP; `archive.extractfile(info)` in TAR `r|` stream mode). `tar.py:L108, L154` clears `archive.members` after each header and drains trailing padding in bounded 64 KiB reads (`tar.py:L159`).
- **C-004 (Archive member selection, terminal validation and error classification):** Mostly satisfied in `src/archive_line_index/backends/zip.py:L43-L120` and `src/archive_line_index/backends/tar.py:L47-L83, L105-L165`, except that `_ZipReader` does not verify at EOF that the total delivered uncompressed byte count matches `self.declared_size` (`R-004`). In `zip.py:L43-L56`, `_select_member` inspects all central-directory entries before returning, rejecting encrypted flags (`flag_bits & (1 | 64)`) with `UnsupportedFormatError`, special POSIX file modes (`stat.S_IFMT(info.external_attr >> 16) not in (0, S_IFREG, S_IFDIR)`) with `ArchiveStructureError`, and zero or multiple regular files with `ArchiveStructureError`. In `tar.py:L68-L83, L105-L164`, `_StrictTarInfo.fromtarfile` requires two consecutive 512-byte zero blocks for terminal EOF and converts damaged or truncated headers into `tarfile.ReadError`; `_first_payload` skips directory entries and rejects non-regular members immediately, while `_TarReader._finish` drains remaining headers (rejecting any non-directory trailing member with `ArchiveStructureError` and any non-zero trailing byte after the end marker with `ExtractionError`). Both adapters wrap raw source handles in `_Source` (`zip.py:L59-L89`, `tar.py:L29-L45`) so genuine source `OSError` instances (`error is self._source.failure`) propagate unchanged while codec/decompressor `OSError` subclasses (`bz2`, `gzip`) map to `InvalidArchiveError` on open or `ExtractionError` during payload reads.
- **C-005 (Bounded incremental delivery):** Satisfied for ZIP and TAR; neither adapter uses background threads or queues, and both forward caller-bounded `size` directly to the underlying member stream after `validate_positive_size(size)`. However, `tests/unit/backends/test_tar.py:L13` parametrizes a 30,000-byte binary payload without explicit parameter IDs, causing pytest on Windows to fail during setup and teardown with `ValueError: the environment variable is longer than 32767 characters` (`R-005`).

### R-004 — `_ZipReader` does not verify that total delivered uncompressed bytes match `declared_size` at EOF

| Field | Evidence |
| --- | --- |
| Baseline location and confidence | `src/archive_line_index/backends/zip.py:L91-L120, L146` (High confidence; confirmed by source inspection and reproduced with a modified `ZIP_DEFLATED` archive in `SC-005`). |
| Observation and consequence | `_ZipReader` exposes `self.declared_size = info.file_size` (`zip.py:L102, L146`), which `make_content_stream` (`stream.py:L218-L221`) treats as trustworthy metadata for `SizeLimitExceededError` prechecks, and sets `self.completed = True` whenever `self._member.read(size)` returns `b""` (`zip.py:L117-L118`). However, Python's `zipfile.ZipExtFile` only checks `_running_crc == _expected_crc` and compressed byte counts; for `ZIP_DEFLATED`, `ZIP_BZIP2`, and `ZIP_LZMA` it never verifies that the total decompressed byte count equals `ZipInfo.file_size` (and for `ZIP_STORED` it only uses `file_size` as an upper read cap without verifying `_left == 0` at EOF if truncated with a matching prefix CRC). Consequently, a ZIP archive whose local/central-directory `file_size` metadata is corrupted (for example, `file_size = 100` or `file_size = 2` for a 6-byte `b"hello\n"` deflated member) completes with `completed = True` instead of raising `ExtractionError`, unlike `sevenzip.py:L248-L250` (`if writer.size() != info.uncompressed: raise ExtractionError(...)`) and `tarfile._FileInFile`. |
| Correction and dependencies | Track total delivered uncompressed bytes in `_ZipReader` (`self._delivered += len(data)`) and verify `self._delivered == self.declared_size` (or raise `ExtractionError("ZIP payload size does not match metadata")` if `self._delivered > self.declared_size` during reads or `self._delivered != self.declared_size` when `not data` at EOF), and add unit tests covering both under-declared and over-declared `file_size` headers. |
| Objective recheck | Verify that `_ZipReader` and `open_content_stream` raise `ExtractionError` when a ZIP member's `file_size` metadata is smaller or larger than the actual decompressed payload stream, and that `tests/unit/backends/test_zip.py` passes. |
| Current disposition | Open (review-only campaign; no source repair performed). |
