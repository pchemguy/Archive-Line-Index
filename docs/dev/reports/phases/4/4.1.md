## Separate code and lifecycle review

Reviewed condition-protected finite transport, immutable callback subdivisions, distinct terminal outcomes, cancellation independent of queue capacity, one non-daemon worker, bounded reader state, failed startup joining and close retry. FIFO payload precedes producer failure; an unbounded public read still raises rather than returning a partial aggregate. Successful close cancels package waits, joins the worker and releases archive/source ownership. No package-owned worker survives successful close.

The 7z adapter validates all exposed member metadata, passes an owned IOBase source to disable dependency parallel file extraction, and forwards callbacks without creating filesystem member paths. The callback writer is synchronized and nonseekable; py7zr 1.1.4 respects this instead of rewinding it on close. Extraction success includes callback size agreement and mandatory owner cleanup before the bridge publishes Finished. The outer adapter can retry archive cleanup after the worker has joined. Source read/seek/tell OSErrors retain their ordinary identity; parsing, unsupported encryption/codec and extraction failures retain distinct categories and dependency causes.

No blocking finding remains. Development checks exposed the dependency's IOBase requirement, an opening-allocation cleanup gap and a raw worker-startup exception; those were corrected before their respective task closures, with observed failing regressions for cleanup and startup classification. This review separately verifies source-I/O identity and persistent archive-close failure: source closure and worker join still occur, a primary CRC error remains primary with cleanup notes, and explicit close can succeed after the injected failure is removed.

## Actual dependency and boundedness evidence

Tested dependency: py7zr 1.1.4, with supported constraint `>=1.1.4,<1.2`. Actual empty/nested regular members, directories, extra metadata files, links, encryption and LZMA2/COPY/deflate/bzip2 payloads are exercised. The adapter explicitly uses max_extract_size=None to avoid an unrelated dependency extraction cap. No password or member-file extraction is requested. The [callback documentation](https://py7zr.readthedocs.io/en/latest/advanced.html) and installed source were inspected; installed version alone is not the evidence.

Actual multi-block archives show public data arriving before producer completion with a slow consumer. Package transport holds at most one queued block of at most 1 MiB and one bounded consumer block; callback inputs and decompressor internals remain dependency allocations. Full-queue cancellation before and after a first read releases source/archive and joins the worker. Real late COPY CRC failure after valid prefix delivery and actual truncation cannot become successful EOF. The <=0.1-second requirement applies to package-controlled cancellation waits (implemented at 0.05 seconds), not dependency calls, scheduling or total close latency.
