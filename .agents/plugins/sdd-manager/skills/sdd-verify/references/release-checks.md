# Package, workflow and release checks

Load for selected release/package acceptance. Use the requested boundary and the accepted [package contract](../../sdd-forge/references/github-packaging.md), not a guessed universal inventory. Verification assesses actual outputs and returns evidence; the coordinated work owner repairs files or performs publication. Local checks do not themselves authorize a live release.

The [artifact-name gate](../../sdd-forge/references/github-packaging.md#artifact-name-gate-and-repair) is a mandatory pre-tag/prepublication check and hosted completion recheck. Derive accepted stable names independently of build output or an upload manifest; a complete/checksummed but version-named set fails. Return specific failing producer/consumer/doc locations to the owning workflow for authorized repair, source publication, rebuild and recheck; verification does not itself edit or publish. Retain passing/blocked evidence for the exact candidate and actual hosted state.

Apply [cross-platform verification scope](check-selection.md#cross-platform-artifacts-and-native-verification) to target artifacts. Unavailable native execution does not prevent an authorized release when the requested artifacts and in-scope checks are complete. Identify cross-built/inspected packages and native tests not run in release evidence and installation instructions; do not claim native-tested compatibility. A missing artifact or failed feasible required check remains distinct.

| Claim | Evidence to obtain |
| --- | --- |
| Git highlights range | Pin target and release line/channel, qualifying tag policy, peeled baseline and ancestry; check complete history/tag discovery, pending-tag exclusion, and complete range identity/parent inventory, latest adequate cumulative campaign summaries, other integration messages including reachable nested merges, and targeted gap messages/diffs. Verify earlier same-campaign bodies are fallback rather than required reconstruction, and original opening pointers stay unchanged across amendments. Verify direct-change/revert coverage, amendment/enclosing-child deduplication and evidence limits; phase/preparation versus implemented-delivery claims remain distinct and refs/tips are discovery only, including phase and plugin-convention `design-docs/*` document-preparation refs. Verify explicit null baseline only for complete initial history. Use [shared Git highlights](../../sdd-forge/references/release-highlights.md). |
| Incremental draft | Confirm ignored/untracked ownership, parseable YAML/full identities, unchanged tag target and baseline → analyzed → target ancestry. Exercise no-op, pending-only update, reverts/cuts, malformed/moved/diverged state and interrupted saves without false watermark advancement. |
| Complete message | Check explicit complete-message routing versus highlights-only/editing-only scope, established template or applicable optional sections, preserved human material, supported factual claims, output ownership/path, body-only Markdown and atomic replacement/no-op behavior. Check separate preparation/final paths: release documents may be committed inside the active revision directory and moved to their final destinations in the release commit. Root `RELEASE-NOTES.md` is the default final path. Verify tracked/untracked ownership, preserved human content and campaign evidence, exact bytes and final-source/ancillary refresh; failure preserves the previous copy. |
| Release commit/tag agreement | Verify current notes provenance/coverage and stated version; matching version alone is insufficient. Resolve the actual default branch and designated development role. Verify a direct default-branch release commit or the merge into default from that development branch; the merge itself is tagged, without another marker. Confirm first-parent placement on the published remote default branch, exact release-commit/notes/GitHub body equality and peeled tag/package/publisher SHA agreement. Reject revision-side commits, ordinary side-history ancestry and wrong merge direction. Recovery retains an eligible pinned commit if default advances; existing-source-only requests do not waive eligibility. No preparation-only marker. |
| Final notes/cleanup | Confirm exact final source coverage, complete UTF-8 body/hash/source transfer to one publisher and actual body readback. Retain the complete-message file after every outcome. Keep internal checkpoints on preparation/draft-only/failure/uncertain or missing readback; delete only an owned internal highlights checkpoint after published-body confirmation unless retention was selected. |
| Package layout/content | Inspect actual member names, duplicates, path/link safety, corruption and declared size limits; compare required members, intentional exclusions, entry points, applicable notices, versions and modes. Explain generated members through the build procedure. |
| Build/source identity | Resolve the exact source SHA/tag, runtime/dependencies and version source; run the declared build from that state into an owned output directory. Compare the candidate with supplied reference contents where relevant. |
| Usable package | Exercise installation/import/startup or another declared consumer check in a suitable controlled environment, without executing untrusted supplied archive scripts. Report unsupported platform coverage. |
| Reproducibility | Repeat under equivalent declared inputs and compare bytes/hashes when this claim is required. Matching inventories alone establish layout, not reproducibility. |
| Stable variants/checksums | Compare actual local/draft/hosted filenames with the independent stable version-free naming contract, including raw HTML, archives, installers, schema and checksum assets. Include every promised variant, only necessary conventional suffixes, no collisions, and matching checksum filenames/exact-byte SHA-256. Exercise the project-local gate with the known bad name before repair and corrected names after rebuild; inspect its direct/CI prepublication wiring. An expected list copied from a faulty generator is not acceptance. |
| Workflow validity | Check YAML plus available Actions validation, trigger/input/permission semantics, checkout identity, build-only effects, matrix collection, one publisher, concurrency and recovery. Parsing is not CI execution. |
| CI success | Identify actual run/ref/source, relevant job conclusions and expected built artifacts. Accepted dispatch, queued state or a success in an unrelated job is insufficient. |
| Hosted release | Read release/tag identity and source, state, complete asset names/sizes/digests, actual latest pointer and URLs. Follow the [release readback](../../sdd-forge/references/github-releases.md#read-back-and-report) procedure. |
| Download integrity | Download exact assets through supported access; compare bytes/hashes with the built files and checksum set. Report metadata-only coverage separately. |

Select positive and relevant failure/recovery checks proportionate to the changes: missing/extra members, unsafe ZIP entries, variant name collisions, absent latest assets, wrong source/version, missing permission, failed matrix build, partial draft upload, uncertain publication and published/immutable conflicts. For highlights use disposable real Git/file fixtures for deterministic identity/parent/merge-message collection and targeted fallback mechanics, plus source/consumer assessment for editorial coverage, consolidation and deduplication. Separate recipe execution from an agent following the workflow: successful fixture scripts do not prove semantic curation, fresh-consumer acceptance or live publisher transfer/cleanup. Use disposable local fixtures or provider mocks where appropriate; mock lifecycle success is not live GitHub acceptance.

Before a hosted check, identify its authorized repository, operation and effects. Do not create a release, dispatch publication or modify immutable/settings policy merely to test instructions. If live CI, installation or download checks are unavailable, return their limits rather than fabricate coverage or declare them passed. Record tested state, actual commands/results and remaining work under [execution and evidence](execution-and-evidence.md).
